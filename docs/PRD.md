# PRD — Onkai Studio Website

## Product statement
A premium, accessible, creative studio website that communicates what Onkai Studio builds, demonstrates real work, presents services, supports visitors, and creates a clear path for potential clients/collaborators to start a project.

## Target audiences
1. Potential clients.
2. People discovering Onkai projects.
3. Developers/designers evaluating the studio.
4. Collaborators and partners.
5. General visitors interested in creative technology.

## Primary CTA
Use one clear primary CTA throughout the site:
**Start a project**

Secondary navigation links may exist, but the visual hierarchy must not create competing primary CTAs.

## Required routes
- /
- /work
- /work/[slug]
- /services
- /studio
- /about (can redirect to or alias Studio if desired, but avoid duplicate SEO pages)
- /playground
- /contact
- /support
- /faq
- /privacy
- /terms

## Homepage sections
1. Navigation.
2. Hero.
3. What Onkai makes.
4. Featured work.
5. Studio/playground statement.
6. Selected experiments.
7. Services.
8. Contact CTA.
9. Footer with legal/support links.

## Trust requirements
The website must expose:
- Privacy Policy
- Terms of Service / Terms & Conditions
- Contact
- Support
- FAQ
- Cookie preferences where applicable

## Technical requirements
- HTTPS in production.
- Cookie consent when optional tracking requires it.
- Metadata and social previews.
- Sitemap and robots.txt.
- Favicon.
- Image alt text.
- Image compression.
- Page-load/performance verification.
- Accessible color contrast.
- Responsive mobile design.
- Custom 404.
- Broken-link checks.
- Client and server form validation.
- Spam protection.
- Privacy-conscious analytics.
- No frontend secrets.

## Out of scope for V1
- User accounts.
- CMS unless later justified.
- E-commerce.
- Admin dashboard.
- Database-backed portfolio.
- AdMob on the company website.
